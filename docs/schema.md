# Schema summary (MVP)

Generated by `supabase/migrations/20261125090000_init.sql`. This file is a quick reference for prompts and reviews — the migration is the source of truth.

## Rules enforced in the database

| Rule                                                                           | Mechanism                                                                                                                                                   |
| ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Only verified students/alumni can review (or add placement data) for a college | RLS `with check` + `has_approved_verification()` + `reviews_set_verification` trigger (sets `is_verified`, raises `42501` without an approved verification) |
| One active review per user per college                                         | Partial unique index on `(user_id, college_id) where status = 'visible'`                                                                                    |
| Content is never hard-deleted                                                  | `content_status` enum (`visible`/`hidden`/`removed`) on reviews, placement_reports, posts, comments, users; no user-facing DELETE policies on content       |
| Pseudonymous identity                                                          | `public.users` has no email column; college emails only as `email_hash` (sha-256 hex) on `verifications`; login email only in `auth.users`                  |
| Average rating hidden until 5 verified reviews                                 | `refresh_college_rating` trigger: `rating_cache` stays NULL and `review_count` counts visible+verified reviews until count >= 5                             |
| RLS on every table                                                             | Enabled on all 12; `mod_actions` has no policies (deny-by-default); moderation writes go through the server-only service key                                |
| Comments depth cap 4                                                           | `comments_depth_cap` check                                                                                                                                  |
| Upvote-only votes                                                              | `votes_upvote_only` check (`value = 1`), unique per (user, target)                                                                                          |

## Triggers

- `on_auth_user_created` (on `auth.users`) → creates the public profile with a unique handle.
- `reviews_set_verification` → derives `is_verified` from approved verifications at insert.
- `reviews_refresh_college_rating` → recomputes `colleges.rating_cache` / `review_count`.
- `comments_refresh_post_comment_count` → maintains `posts.comment_count`.
- `votes_refresh_targets` → maintains `posts.score` / `comments.score` / `reviews.helpful_count` and user `karma`.
- `*_touch_updated_at` → `updated_at` on mutable tables.
